# Testnetz Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Testnetz, das beweist, dass sich das Verhalten der Anwendung nicht geaendert hat — Endpunkt-Tests fuer `server.ts` und Durchspiel-Tests im echten Browser — damit spaetere autonome Wartungsroutinen ueberhaupt eine Grundlage haben.

**Architecture:** `server.ts` wird in eine testbare Fabrik `erzeugeApp()` (neu: `src/server/app.ts`) und einen duennen Starter zerlegt. Darauf setzen Vitest-Endpunkttests mit supertest gegen eine `:memory:`-Datenbank auf, wie es `src/server/store.test.ts` bereits vormacht. Darueber liegen Playwright-Tests, die den gebauten Client gegen eine eigens angelegte Testdatenbank fahren. Eine Abdeckungsschwelle in der CI haelt das Netz gespannt.

**Tech Stack:** TypeScript, Express 4, Socket.IO 4, better-sqlite3, Vitest 3, supertest, Playwright, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-25-autonome-wartung-design.md`

## Global Constraints

- **Sprache:** Bezeichner, Kommentare und Testnamen auf Deutsch, ohne Umlaute in Dateinamen. Bestehendem Stil folgen (`sperrfrist.test.ts`, `store.test.ts`).
- **`tsconfig` ist nicht `strict`.** Kein `any` neu einfuehren; an der API-Grenze vorhandenes `any` nicht ausweiten (Issue #19).
- **Farben nur ueber Rollen** (`bg-flaeche`, `text-leise`). Kein `slate-`/`blue-`/`bg-white` in neuem Code.
- **Datumsstrings sind die Wahrheit:** Wuensche an `YYYY-MM-DD`, Monate an `YYYY-MM`, jeweils als String.
- **`MIN_PASSWORD_LENGTH = 8`**, `SHIFT_TYPES = ['Früh', 'Spät', 'Nacht', 'Frei']` (aus `src/types.ts`).
- **Ein Manager ist nie gesperrt:** `sperrfristFuerMonat` gibt `gesperrt: rolle === 'Manager' ? false : abgelaufen`.
- **Niemals committen:** `data.sqlite*`, `sitzungsgeheimnis`, `db.json*`. Testdatenbanken gehoeren unter einen ignorierten Pfad.
- **Jeder Commit braucht einen `CHANGELOG.md`-Eintrag** — die Schleuse (`tools/pruefe-schleuse.mjs`, `PreToolUse`-Hook) laesst `git commit` sonst nicht durch. Ein Satz unter `## [Unreleased]` genuegt.
- **Commit-Trailer:** jeder Commit endet mit
  `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- **Branch:** alles auf `feature/autonome-wartung`, nicht auf `main`.

**Interfaces:**
- Consumes: `erzeugeApp` aus Task 1.
- Produces: aus `e2e/hilfe.ts`, worauf **alle** spaeteren Spec-Dateien bauen:
  ```ts
  export const KONTEN: {
    leitung: { name: string; passwort: string };
    mitarbeit: { name: string; passwort: string };
    zweite: { name: string; passwort: string };
  };
  export const OFFENER_MONAT = '2099-06';
  export const GESPERRTER_MONAT = '2020-01';
  export async function anmelden(seite: Page, konto: { name: string; passwort: string }): Promise<void>;
  export async function zumMonat(seite: Page, monat: string): Promise<void>;
  ```

**Warum eine eigene `hilfe.ts` und nicht die naheliegenden Orte:**

- **Nicht aus einer `.spec.ts` importieren.** Playwright sammelt Tests beim
  Import einer Datei ein. Wer `anmelden` aus `anmeldung.spec.ts` importiert, zieht
  deren drei Tests in jede importierende Datei hinein — sie liefen dann fuenfmal.
- **Nicht aus `server-starten.ts` importieren.** Die Datei startet beim Import
  einen Server. Ein Import aus einem Test wuerde in jedem Testprozess einen
  zweiten Server auf demselben Port hochziehen.

Beides sind Fehler, die als „unerklaerliche Doppelausfuehrung" bzw. `EADDRINUSE`
auftauchen und viel Zeit kosten. Deshalb: eine Datei ohne Tests und ohne
Nebenwirkungen.

## Task 13: Der Dunkelmodus-Durchgang

Der einzige automatische Weg, eine eingestreute `bg-white` zu erwischen, bevor sie nachts auf dem Telefon auffaellt.

**Files:**
- Create: `e2e/dunkelmodus.spec.ts`

- [ ] **Step 1: Test schreiben**

Erstelle `e2e/dunkelmodus.spec.ts`:

```ts
import { expect, test } from '@playwright/test';
import { anmelden, KONTEN, OFFENER_MONAT, zumMonat } from './hilfe';

test.use({ colorScheme: 'dark' });

/** Wahrgenommene Helligkeit einer `rgb(...)`-Angabe, 0 bis 1. */
const helligkeit = (farbe: string): number | null => {
  const treffer = farbe.match(/rgba?\((\d+),\s*(\d+),\s*(\d+)(?:,\s*([\d.]+))?\)/);
  if (!treffer) return null;
  const [, r, g, b, a] = treffer;
  if (a !== undefined && Number(a) < 0.5) return null; // durchsichtig zaehlt nicht
  return (0.2126 * Number(r) + 0.7152 * Number(g) + 0.0722 * Number(b)) / 255;
};

test('im Dunkelmodus ist der Hintergrund dunkel', async ({ page }) => {
  await anmelden(page, KONTEN.mitarbeit);
  const farbe = await page.evaluate(() => getComputedStyle(document.body).backgroundColor);
  const h = helligkeit(farbe);
  expect(h, `body-Hintergrund ist ${farbe}`).not.toBeNull();
  expect(h!).toBeLessThan(0.3);
});

test('keine sichtbare Flaeche leuchtet weiss', async ({ page }) => {
  // Eine eingestreute Farbe bricht den Dunkelmodus still. Deshalb: neue Rolle
  // in index.css anlegen statt einen Wert einstreuen.
  await anmelden(page, KONTEN.mitarbeit);
  await page.getByTestId('monatswahl').fill(OFFENER_MONAT);

  const auffaellige = await page.evaluate(() => {
    const treffer: string[] = [];
    for (const el of Array.from(document.querySelectorAll('body *'))) {
      const kasten = el.getBoundingClientRect();
      if (kasten.width < 8 || kasten.height < 8) continue;
      const stil = getComputedStyle(el);
      if (stil.visibility === 'hidden' || stil.display === 'none') continue;
      const m = stil.backgroundColor.match(/rgba?\((\d+),\s*(\d+),\s*(\d+)(?:,\s*([\d.]+))?\)/);
      if (!m) continue;
      if (m[4] !== undefined && Number(m[4]) < 0.5) continue;
      const hell = (0.2126 * +m[1] + 0.7152 * +m[2] + 0.0722 * +m[3]) / 255;
      if (hell > 0.75) {
        treffer.push(`${el.tagName.toLowerCase()}.${el.className} → ${stil.backgroundColor}`);
      }
    }
    return treffer;
  });

  expect(auffaellige, `Helle Flaechen im Dunkelmodus:\n${auffaellige.join('\n')}`).toEqual([]);
});

test('alle drei Ansichten bleiben dunkel', async ({ page }) => {
  await anmelden(page, KONTEN.mitarbeit);
```
